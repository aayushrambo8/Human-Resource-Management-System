# Integration Risks (Phase 1 — observation only; nothing changed)

| # | Risk | Evidence | Severity | Suggested resolution (Phase 2) |
|---|---|---|---|---|
| 1 | **Middleware/session mismatch blocks every protected route.** `src/middleware.ts` reads cookies `hrms.accessToken`/`hrms.refreshToken`; `src/lib/api-client.ts` writes tokens only to sessionStorage. After login, every navigation is redirected to `/login`. | source comparison | **Blocker** | Decide storage model (see authentication-decisions.md #2) and align middleware + client. |
| 2 | **CORS origin stale.** Backend default allowlist is `http://localhost:5173` (old Vite port); Next dev runs on 3000. Direct cross-origin calls from the Next app will be rejected until `HRMS_CORS_ALLOWED_ORIGINS` includes it. `docker-compose.yml` defaults it to `http://localhost:8080`. | `application.yml`, `SecurityConfig`, compose | **Blocker** (dev) | Set env var per environment; decide whether to use the Next rewrite proxy instead (which avoids CORS entirely). |
| 3 | **Frontend Docker build broken.** Committed `frontend/Dockerfile` builds the deleted Vite app (`index.html`, `vite.config.ts`, `nginx.conf` — all deleted in the working tree); compose passes `VITE_API_BASE_URL`. | git status, Dockerfile, compose | **Blocker** (deploy) | Rewrite Dockerfile for `next build` (standalone output) + compose args. |
| 4 | **Two competing API URL conventions.** axios hits `${NEXT_PUBLIC_API_URL}/api/...` directly while `next.config.ts` defines an unused rewrite `/api/backend/:path* → …/api/:path*`. | `api-client.ts`, `next.config.ts` | Medium | Pick one (same-origin rewrite/proxy recommended for self-hosted LAN deployment; then CORS risk #2 disappears). |
| 5 | **Stale env example.** `frontend/.env.example` still documents `VITE_API_BASE_URL`; the app reads `NEXT_PUBLIC_API_URL`. | file contents | Low | Update example in Phase 2. |
| 6 | **Broken lint script.** `npm run lint` → `next lint` but no ESLint dependency/config exists; oxlint is the configured linter. | package.json, `.oxlintrc.json` | Low | Change script to `oxlint src` (no new dependency needed). |
| 7 | **Dead navigation links.** `/employees/new`, `/departments/new`, `/leave/new`, `/leave/[id]` are linked but routes don't exist (404). | route tree vs `<Link href>` | Medium | Implement forms or remove links during module build-out. |
| 8 | **Unpaginated list endpoints.** `/api/employees`, `/api/departments`, `/api/companies`, `/api/leaves` return full tables; dashboard fetches 100 attendance rows. Dataset growth → payload/perf issues. | controllers | Medium (scale) | Add pagination/search (backend change; contract addition). |
| 9 | **No dashboard aggregation endpoint.** KPIs are computed in the browser from full lists; leave/presenteeism analytics impossible. | controllers | Medium | Accept for v1 with small data, or add read-only stats endpoints later. |
| 10 | **Date/time semantics.** Backend `punchTime`/`reviewedAt` are UTC instants; frontend formats with `Intl.DateTimeFormat` in the **browser's** local zone. Late-evening/early-morning punches can render on the "wrong" day; no timezone is defined anywhere (JVM default). `joiningDate`/leave dates are date-only strings parsed by `new Date('yyyy-MM-dd')` (UTC midnight — can shift a day in negative-offset zones). | `format.ts`, DTOs | Medium | Decide institutional timezone; format dates without timezone shifting (or pass explicit zone). |
| 11 | **Error body consistency UNKNOWN.** 404/409 are ProblemDetail; 401 is an empty `sendError` body; validation-error payload shape was not runtime-verified. Frontend `getErrorMessage` expects `detail`. | `ApiExceptionHandler`, SecurityConfig | Low-Medium | Verify against a running server in Phase 2; extend `getErrorMessage` if needed. |
| 12 | **Frontend/backend type drift risk.** Types are hand-duplicated in `src/lib/types.ts` (currently aligned). `Employee.status` literal union omits `RESIGNED` (covered by `\| string`). | types comparison | Low | Consider generating types from the contract; at minimum re-verify on every backend change. |
| 13 | **Settings page contains stale claims** ("Spring Boot 3") — cosmetic misinformation. | settings page | Low | Correct text. |
| 14 | **Empty artifact directory** `employees/[id` (no closing bracket) beside the real `[id]` route — Windows tooling hazards. | filesystem | Low | Delete in Phase 2. |
| 15 | **Design reference missing.** `design-reference/hrms-dashboard.png` referenced by the brief is absent; the audit could not verify design conformance. | glob | Medium (design phase) | Obtain the reference before Phase 2 design-token work. |
| 16 | **Auth premise conflict.** Brief says auth is unimplemented; code (committed) implements it fully. Planning on the brief alone would duplicate/conflict with existing code. | this audit | **Blocker** (process) | Resolve via authentication-decisions.md before Phase 2. |
| 17 | **Uncommitted migration.** The entire Next.js app is untracked and the Vite app deletion is unstaged; the working tree is not reproducible from the last commit. | git status | Medium | Commit the migration as a reviewed unit before feature work. |
| 18 | **`logout` requires a Bearer token** (not in permitAll). Frontend sends one, so it works — but a token-less logout call would 401. Contract quirk to remember. | SecurityConfig vs AuthController | Info | None required. |
| 19 | **Version-coupling.** Spring Boot 4.1.1 + Java 21 (very recent line) and Next 15.5 + React 19 + TS 6 + Tailwind 4 are all current-generation; host toolchains must match (Java 21, Node ≥22 recommended). No inter-repo incompatibility found. | pom.xml, package.json | Info | Pin CI toolchains. |
